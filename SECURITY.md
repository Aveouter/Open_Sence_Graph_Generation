# Security Policy

## Reporting

If you find a security issue, do not open a public issue with exploit details.
Contact the repository owner privately through GitHub and include:

- affected commit or release,
- reproduction steps,
- impact,
- any suggested mitigation.

## Scope

Security reports may include dependency vulnerabilities, unsafe checkpoint or
artifact loading behavior, credential exposure, CI token misuse, or workflows
that could write untrusted content to the repository.

Research result disagreements, benchmark variance, and unsupported datasets are
not security issues; use GitHub issues or the reproduction workflow for those.
